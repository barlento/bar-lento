## How to publish a change (the only job that needs code)
Edit the files, commit, `git push origin main`. That's it — Vercel builds and publishes automatically. No build step, no npm install locally (Vercel installs `web-push`).
Push directly to `main` (no PR needed) unless the owner asks otherwise. If a direct push is refused, push a branch and tell the owner to tap **Create PR → Merge**.
Verify after ~90 s at https://bar-lento.vercel.app (add `?v=<n>` to bypass caches). `*.vercel.app` may be unreachable from the sandbox network — say so instead of guessing.

## Golden rules from the owner
- **Simplicity first** ("più semplice e veloce"). One obvious button beats three clever ones. Marta must never need Claude.
- **Look (owner's decision 2026-09-19, "serious, Apple-like, sellable product")**: light grey page `#F5F5F7`, white cards, hairline borders `#E5E5EA`, near-black text `#1D1D1F`, cool greys, ONE blue for actions `#0071E3`; green/red only as semantic status; Inter everywhere (headings 600, tight tracking), IBM Plex Mono for times; **no emoji anywhere in the UI** (labels are plain words, ✓/✕/›/⋯ glyphs only), neutral black avatars, no confetti, no sway/bounce, hairline shadows, blurred backdrop behind sheets. Tokens in `:root`, overrides at the end of `<style>`. Opening **splash** (`#splash`): "Bar Lento" white serif (Newsreader, only place it is used) on near-black `#141311`, ~3 s then fade, tap to skip, skipped on the silent auto-update reload (`sessionStorage bl_skip_splash`). Toasts at the TOP. Button labels stay on one line: keep them short.
- Light, readable theme; must look great on iPhone (installable PWA, home-screen app) and on PC. Playful "alive" effects: pulsing LEDs, rising cards, confetti — never at the cost of clarity.
- Personal access is mandatory: the schedule is blurred behind "Who are you?" until a person enters their PIN (or the manager logs in). Each person can confirm ONLY their own shifts (server-checked), via a two-step popup (tap shift → tap Confirm).
- Notifications: ONLY (a) "new week posted" and (b) one batched summary of changes that affect employees (shift added/removed/time changed, day closed/opened). Never spam. Quiet hours 11 PM–10 AM New York.
- No public comparisons between employees (Marta's request): personal stats only for staff, rankings only in Manager mode. Exception decided by the owner: the **⏱ Time clock** (who punched in/out, times, past days) stays visible to every signed-in employee — it is operational info, not a ranking. Don't restrict it.
- **Toast is read-only, always.** Clock-ins/outs happen ONLY on the real Toast POS terminal with the employee's own account. The site just mirrors them (history, confirmation, a nice extra to check from home). Never add a way to punch in/out, edit or create time entries from the site — for anyone, manager included.
- Past weeks are a locked legal archive: never editable/deletable; removing a person deletes only their **upcoming** shifts.
- Manager password lives only in Vercel env `admin_password` (any case). Never print secrets in chat, code or logs.

## Architecture (vanilla, no framework)
- `index.html` — the whole UI (staff + manager) in one file: CSS, i18n dict `I18N.en/it` (`t()`, `data-t`), IIFE app. Polls `/api/data` every 45 s. Service worker `sw.js` (push display only, no caching). PWA: `manifest.webmanifest`, `icons/`.
- `api/*.js` — Vercel serverless functions (Node, CommonJS):
  `data` (GET schedule / POST save with optimistic `version`, 409 on conflict; removing a staff name also wipes their PIN + devices), `login`, `confirm`, `log`, `export` (CSV archive), `push` (subscriptions), `notify` (manager flush), `toast` (POS: `status`, `today`, `clock`, `employees`, `who`), `me` (personal access: `begin`/`create`/`login`/`logout`, `who`, `hours&week=` per-person Toast entries, manager `list`/`reset`).
- `lib/store.js` — Upstash Redis via REST (env prefix auto-detected KV_/UPSTASH_REDIS_/STORAGE_/REDIS_); seed fallback `data.json`. Keys: `barlento:schedule`, `barlento:confirm`, `barlento:log`, `barlento:pending*`, `barlento:announce`, `barlento:push`, `barlento:toast:*`, `barlento:pin` (name → scrypt hash), `barlento:sessions` (device token → name), `barlento:rules_ack` / `barlento:rules_ack_archive` (House Rules acknowledgments, legal record).
- `lib/accounts.js` — staff PIN accounts: 4 digits, scrypt+salt, 5 wrong tries → growing lock (5→60 min), random 48-hex device token in header `x-staff-token` (localStorage `bl_me_token`/`bl_me_name`), `resetPin` = clear PIN + sign out everywhere.
- `lib/diff.js` — computes changes between saves → history log + "notable" changes for the batched push.
- `lib/push.js` — Web Push (VAPID; public key in file, private in env `VAPID_PRIVATE_KEY`), `flushPending` with quiet hours.
- `lib/mail.js` — outgoing email for the signed copy of the House Rules: SMTP via nodemailer (`SMTP_HOST/PORT/USER/PASS`, e.g. Google Workspace app password) or Resend (`RESEND_API_KEY`), `MAIL_FROM` optional, `MAIL_WEBHOOK_URL` for local tests. `enabled()` → `features.mail`. **LIVE via Resend** since 2026-09-18: `RESEND_API_KEY` + `MAIL_FROM` on Vercel, domain barlentony.com verified (DKIM TXT `resend._domainkey` + CNAME `rsend`/`send` on Squarespace DNS; Google MX/SPF/DKIM untouched, receiving stays OFF). If not configured the acknowledgment is still recorded; Marta can re-send later with the ✉ button in Staff.
- `lib/toast.js` — Toast POS Standard API (read-only): login, restaurant auto-discovery, employees (paginated), time entries, `dayStatus`, `autoMap` (fuzzy first-name matching so nobody maps names by hand). Env: `TOAST_CLIENT_ID`, `TOAST_CLIENT_SECRET` (optional `TOAST_RESTAURANT_GUID`).
- `documents.js` — staff policies (see 📂 Documents below), `docs.html` printable versions.
- Data model: `{staff[], birthdays{name:YYYY-MM-DD}, toastMap{name:guid}, weeks{<MondayISO>:{mon..sun:[{id,name,station,start,end}], notes:{day:{status:''|closed|holiday|half|event,text,open?,close?}}}}}`.

## Features already live (don't rebuild — extend)
Weekly view with tabs; today hero with LED; typed confirmation; manager mode (add/edit/delete shifts, staff + birthdays with confetti popup, day closures with presets incl. half-day hours, US holidays auto-detected, one-tap **New week** (copy last / empty), delete current/future week with double confirm, change history, CSV export, Notify team, IT/EN); push notifications with bell button; new-week popup once per device; **⏱ Time clock** button for everyone (Toast clock-ins/outs, day navigation, live counter) and clock badges on today's shifts.
**Personal access (name + PIN)**: first visit → "Who are you?" name grid → create/enter 4-digit PIN on a big keypad → device remembered (token). Header button 👤 + strip "Hi Marco · Next shift…" with two buttons, own shifts tagged YOU. **📅 My week**: week nav, tiles scheduled / worked (Toast) / difference, per-shift clock-ins, tap to confirm, "Not you? Switch", "Log out here". **🌟 Week in review** popup once per person per week (`/api/me?action=recap&week=`): last week vs the week before, always encouraging (more hours, punctuality up, early bird, gentle nudge) — never negative. **⭐ My stats** (`/api/toast?action=mystats`, identity from the PIN token, or manager + `&name=`): ONLY own hours, on-time % (after 3 scheduled shifts), streak, badges, encouraging message, anonymous team totals — never other people's numbers or a rank. Manager **Staff**: one clean row per person (avatar, name, status line "PIN ✓ · Rules ✓ · Docs k/5" or "Hasn't signed in yet", 🎂 date, ›); tapping opens the **person sheet** (`#personOverlay`, `openPerson`): birthday, access + **🔑 Reset PIN** (double tap; also signs out their devices), documents with dates + ✉ re-send, **📅 View week**, remove (double tap). **Day settings** = 2×2 tiles (Open / Half day / Private event / Closed — other; + holiday tile when a US holiday): Open/Event/Holiday save on tap, Half day reveals hours, Closed reveals the reason; the status `<select>` is hidden and only drives the logic. **🏆 Team ranking** exists only in Manager mode (`?action=leaderboard`, password required; `lib/leaderboard.js`): Hours + On-time columns, podium, live re-ordering. The manager (Marta) explicitly asked that staff never see comparisons — keep it that way.

**📜 House Rules** (`rules.js` = the text, dual-mode: `window.BL_RULES` in the browser, `require()` on the server; `rules.html` = printable page): shown ONCE per version right after the PIN login, blocking (also for the manager if she signed in with her own name): read to the end → email → checkbox → "I have read and agree" → `POST /api/me {action:"ackRules"}`. Server checks the version against `rules.js`, stores name/email/time/device + sha256 of the text in `barlento:rules_ack` (first acknowledgment of a version wins, older versions kept in `history`), logs a line in the change history. Removing a person moves the record to `barlento:rules_ack_archive` (never deleted; manager `list` returns it as `formerAcks`). On acknowledgment the full text + electronic signature block (Toast full name, email, NY date/time, version, text fingerprint, device) is emailed to the person with a copy to `RULES.copyTo` (simoneviola@barlentony.com); the email field is prefilled with the person's Toast email. Roster shows "Rules ✓ date · email" / "not acknowledged yet" and a ✉ re-send button when mail is configured. Contacts: simoneviola@ / martanicita@ / chiaratinazzi@barlentony.com (no dots). `version: "2026-09-18"` is LIVE; a new version asks everyone again; typo/email fixes may keep the version (the hash proves what was signed). Text is English only, 18 sections, reviewed against NY law by a panel (cashless ban NYC Admin Code §20-840 → manager handles cash; uniform wash-and-wear + enough shirts 12 NYCRR 146-1.7; CROWN Act hair; §201-d cannabis "observable signs"; §52-c monitoring notice wording; §193 no deductions; ESSTA sick/safe leave; §206-c lactation; NLRB-safe privacy/social media wording; workers' comp reporting; off-the-clock work). **📂 Documents** (`documents.js` = the texts, dual-mode like `rules.js`; `docs.html?id=` printable, with the complaint form appended for `harassment`): the legal policies every person reads and signs like the House Rules, one popup at a time right after the rules. Five entries: 🛡 `harassment` (NYS model Sexual Harassment Prevention Policy 2024, adopted in full + Bar Lento reporting summary + complaint form; report to the Owners), 🎓 `training` (annual NYS model video EN/IT, `kind:"training"`, version = calendar year, re-asked every January), 🩺 `pto` (NYC Protected Time Off / safe & sick leave as amended 2026-02-22: 1h per 30h up to 40h paid, 32h unpaid immediately, 20h paid prenatal, calendar year Jan–Dec, documentation only after >3 consecutive days, no minimum increment, official DCWP Notice EN/IT linked), 💵 `tips` (no pool; card tips via Toast Payroll in full, cash tips kept and declared in Toast, owners/manager never share, §196-d), 🍼 `lactation` (NYS DOL model policy 2024 revision, paid 30-min breaks, space = a private back-of-house area agreed in writing, no dedicated room; `version:"2026", yearly:true` like the training because the law wants it handed out every year). Flow (owner's choice, "one read, one signature"): after the rules, ALL unsigned policies open together as ONE blocking packet "📂 Your documents (4)" (`openPacket`: every text in full, NO email field (the email typed once at the House Rules is reused: `signedEmail()`, shown as "Signing as Name · email"; server `signingEmail()` falls back to the rules/previous ack email), one checkbox, one **Sign** → `POST {action:"ackDocs", ids, versions, email}` → one record per document, ONE email with everything to the person + ONE proof email to the owner, `mail.packetCopy`); only the 🎓 training may wait with **Later** until `trainingDays` (30) after the later of version date / PIN creation (`since`) (one reminder per device per day, `bl_docs_snooze`), then it blocks too. `deadlineDays` (7) is only used for the status text of unsigned policies. Server: `POST /api/me {action:"ackDoc", id, email, version}` (token, first-ack-wins, history, sha256 of the doc JSON, emailed copy to the person + separate "✓ X acknowledged…" proof email to `copyTo`), keys `barlento:doc_ack:<id>` and archive `barlento:doc_ack_archive` on staff removal; `who` returns `docAcks`, `since`, `docsVersions`; manager `list` returns per-person `docs`; `POST {action:"sendCopies", name}` re-sends to the person only (no owner copy again): House Rules + one packet email with every signed document (roster ✉) — only documents whose signed version is still the live one (same text as the fingerprint); `myCopies` is throttled to once per 10 min per person (429). First acknowledgment is written with HSETNX (double tap = one record). UI: My week → **📂 My documents** (badge = how many to sign) lists rules + docs with signing dates, tap to reread/print, **✉ Email me my signed copies** (`POST {action:"myCopies"}`, token, own recorded emails only); roster shows "📂 Documents k/5" + icons. Changing a document's `version` asks everyone again. Owner duties outside the app remain: post the DCWP Notice + NYC CCHR anti-harassment poster in the staff area, make Toast Payroll accrue/print protected time off on pay statements, hand out the LS 54 pay notice at hire, confirm no card fees are deducted from tips.
